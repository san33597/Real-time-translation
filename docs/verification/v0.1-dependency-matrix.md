## Translation policy (R0 decision updated 2026-10-09; R4 not implemented)

- **Selected/default:** Google ML Kit Translate `com.google.mlkit:translate:17.0.3` as the first-pass English→Simplified Chinese engine. Model is downloaded through the ML Kit SDK and subsequent inference happens on-device. It has **not** been integrated in the R1 APK.
- **Explicit trade-off:** ML Kit does **not** upload translation input/output to Google for inference, but the SDK may contact Google and transmit performance/usage/device/application metrics. Firebase Remote Config and installations may be used for diagnostics. Therefore no zero-telemetry or network-zero-runtime promise for this mode. Official disclosures: https://developers.google.com/ml-kit/terms , https://developers.google.com/ml-kit/android-data-disclosure , https://developers.google.com/ml-kit/language/translation/android .
- **Optional DeepSeek optimization (default OFF):** after ML Kit returns a draft for the same stable/final English sentence, the user may enable cloud refinement with their own API key; send only approved `sourceEnglish`, `draftChinese`, and optionally explicitly approved limited glossary/context. Raw PCM/audio, interim ASR partials, full history and unrelated device metadata are prohibited. The setting must be clearly visible and revocable.
- **No provider switching or hidden fallback:** ML Kit is always the first pass. DeepSeek never runs when disabled, is not a replacement for the primary translator, and may not block local subtitles. Errors, offline state, API quota or late cloud responses leave the draft unchanged.
- **Subtitle version gates:** tie the ML Kit draft and optional optimization to `sessionId/audioEpoch/utteranceId/revision` plus a provider/request generation; reject stale, cancelled, post-lock, superseded or out-of-order responses. Prevent flicker by updating only the same live sentence while its revision remains current; no editing historical or already scrolled subtitles.
- **Key handling:** accept user-supplied DeepSeek credentials only, use Keystore-backed encrypted storage (or reviewed equivalent) in private no-backup storage, redact logs/errors, TLS, show cost and data disclosure before enabling, and cancel requests on disabling. Do not embed static API keys in APK, source or Git.
- **Architecture:** `LocalMlKitTranslator` performs translation; `OptionalDeepSeekRefiner` conditionally post-processes the local draft. Provider/result coordination stays behind interfaces to permit later cloud vendors. Actual design: `docs/decisions/2026-10-09-provider-architecture.md`.
- **Open gates:** ML Kit language-model readiness, English→Chinese correctness, latency, licenses/disclosures, user-visible metrics explanation, on-device runtime network review; cloud opt-in, credential security, provider egress and subtitle race/error tests.

## R1 privacy decision

R1 uses fake resources only. Declared permissions: RECORD_AUDIO, foreground service and its two types, and POST_NOTIFICATIONS. ACCESS_FINE_LOCATION and broad storage permission are forbidden. Internet permission is intentionally deferred until model download is implemented. `allowBackup=false` and Android 12+ data extraction exclusions protect future local history by default; actual transfer behavior remains a device acceptance case.

## Remaining gates before R2/R3/R4

- **CLOSED (decision):** user selected ML Kit primary translation plus optional, default-OFF DeepSeek refinement. Earlier Option B selection is superseded.
- **OPEN (implementation):** integrate and verify ML Kit model lifecycle, user-visible SDK metrics disclosure, local latency, result ordering, and optional cloud consent/security/egress.
- Record target phone API/ABI and actual foreground-service permission flow results.
- Pin native AAR URL/revision/SHA-256 and exact model-file bytes/checksums/licenses before R3.
- Run Gradle unit, lint and assemble; capture evidence from GitHub CI and real Android device.
- Record third-party licenses before packaging assets.

R0's translation policy is now **ML Kit first; optional, opt-in DeepSeek refinement**. Native ASR artifact checks, target device/ABI, implementation testing and remaining R1 edge-case acceptance remain open. The R1 demo has **no ML Kit or DeepSeek code**; SDK diagnostics preclude a zero-telemetry claim once ML Kit is integrated.
