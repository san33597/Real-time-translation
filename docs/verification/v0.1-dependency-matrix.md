## Translation (R4 privacy blocker)

- Proposed: Google ML Kit Translate 17.0.3 **candidate only**; not added to Gradle dependencies or packaged in R1.
- ML Kit documentation states that feature SDKs collect device/application/performance information; on-device translation does **not** imply zero SDK metrics network transfer. See https://developers.google.com/ml-kit/android-data-disclosure and https://developers.google.com/ml-kit/terms.
- **Unresolved product decision:** whether to accept official disclosed SDK metrics while forbidding any audio/text upload, or require strict zero telemetry and evaluate a different, verifiable on-device translator.
- Until the decision is recorded, do not integrate ML Kit, secretly relax the promise, or substitute a cloud API.
- Separate tests will be needed for content egress and metrics egress; offline inference alone does not prove zero SDK network traffic.

## R1 privacy decision

R1 uses fake resources only. Declared permissions: RECORD_AUDIO, foreground service and its two types, and POST_NOTIFICATIONS. ACCESS_FINE_LOCATION and broad storage permission are forbidden. Internet permission is intentionally deferred until model download is implemented. `allowBackup=false` and Android 12+ data extraction exclusions protect future local history by default; actual transfer behavior remains a device acceptance case.

## Remaining gates before R2/R3/R4

- Record user's explicit ML Kit metrics decision.
- Record target phone API/ABI and actual foreground-service permission flow results.
- Pin native AAR URL/revision/SHA-256 and exact model-file bytes/checksums/licenses before R3.
- Run Gradle unit, lint and assemble; capture evidence from GitHub CI and real Android device.
- Record third-party licenses before packaging assets.

R0 review and R1 implementation are separate from **fully closing R0**: the above privacy and native artifact gates remain open, and this file must not be misread as approval.
