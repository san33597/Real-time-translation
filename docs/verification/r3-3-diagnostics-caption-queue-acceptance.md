# R3.3 A+B：原始识别诊断 / 有序字幕队列

基线：R3.2（`feat/r3-2-caption-segmentation`）。R3.3 不替换 Sherpa-ONNX 模型、不增加声音预处理、不引入 ML Kit/DeepSeek。

## A. 原始识别诊断

应用页面的「展开识别诊断：ASR 原文 vs 字幕」显示：
- 最近一个有效 ASR Partial 或 Final 的**原始识别全文**（页面目前只展示末尾 450 字，状态内的原文不截断）。
- 当前实际显示在两行悬浮窗的已确认片段。
- 最近 12 条 Partial / Final 的类型、utterance/revision、时间戳及末尾摘录；UI 展示最近 6 条。
- Partial/Final 数量、已显示片段、等待中的片段、队列溢出数、已确认前缀被模型改写的次数。
- 原有音频帧数和丢帧统计保持不变。

这些诊断数据仅在本机内存中保留，**停止采集或服务退出即清空**，不保存语音或转录文件，不上传数据；诊断面板默认折叠。

## B. 按词序显示已确认内容

- 移除 R3.2 的 `LiveCaptionSegmenter` 尾部跳词算法。R3.2 中仅展示最后 3 个词、最多 64 字的硬截断无法保证中间内容出现。
- 在同一个 ASR utterance 内，连续两个 Partial 保持一致的前缀作为已确认词；Final 补齐剩余词。**未确认的临时 Partial 不作为最终词显示**，避免显示随模型改写而震荡。
- 已确认词按原顺序组成最多 60 字 / 9 词的片段。一个片段至少显示约 950ms，队列积压时动态缩短到 650ms / 400ms；在无新识别时仍由 Service 每 100ms 驱动继续播放。
- 最多排队 48 个短片段。极端积压下可能溢出，系统**明确增加溢出计数**，不宣称无界缓冲能同时做到零丢词与零延迟。
- 句与句之间的停顿只用来影响后续版本的排版；R3.3 不根据无标点文本猜测精确人物/语义分句。
- `EnglishSubtitleState.partial` 与 `committed` 保留完整原始文本，不因字幕窗口的两行限制而截断；仍沿用现有悬浮窗权限、隐藏机制和通知停止。

## 真机重点对照

1. 覆盖安装 v0.3.3，不要卸载已导入模型的应用。
2. 在测试视频中听取一段明显的快速短对话，例如 `Here you are. Thank you.`，观察两行悬浮字幕有无跳词。
3. 切回翻译应用，**展开诊断区**。如原始 ASR 文本就没有 `Here you are`，属于模型漏识别；如原始 ASR 有此词而字幕未显示，查看待显示片段数量、队列溢出和模型修订计数，属于字幕调度或识别修订问题。
4. 快速连续播放两分钟，检查字幕队列不会长期增长，显示延迟不会持续积累。所有溢出必须可见且可量化。
5. 在剧情场景和单人朗读场景各测试一段，比较两者的漏词情况；正式模型横向比较留到 R3.3 C/D。
6. 无声音、切回应用、切回视频、悬浮窗撤权、通知「停止采集」、媒体授权撤销均应正常。

注意：R3.3 A+B **不能恢复 ASR 从未识别的英语**，也不等于提升声学模型的准确率。诊断数据在停止时清除，请在运行期间展开检查。
