# R3.2: 英文字幕自动分段与精简悬浮显示

**基线：** R3.1 现有录音、sherpa ASR、权限授权与悬浮窗。独立开发分支 `feat/r3-2-caption-segmentation`；R2 / R3 / R3.1 原分支不改。

## 问题和改进
- 原 R3.1 即使讲话转到下一句也可能把无标点的识别结果连续拼成一大段，因为 ASR 输出在真正 endpoint 之前可能一直增长。
- 旧悬浮窗最多 3 行、160 字符，展示太多。R3.2 改成 **最多 2 行、最多 64 字符**，优先显示**最新英语片段**。应用内同样改成较短的当前字幕，而不是全部累计 final。
- 通过 `LiveCaptionSegmenter` 基于**新单词出现前约 1100ms 的无文本更新时间**来推断新显示片段；持续增长到 13 个单词则做一次展示窗口的自然截段。边界仅影响 UI，不当成可靠的语义句号，不向 ASR 注入静音、不重置模型、不更改原生解码性能。
- `EnglishSubtitleState.partial` 和 sealed `committed` **仍保留 ASR 原始完整文本**，不会因为裁剪悬浮字幕而丢词，也不会虚构标点。
- 字幕结果停止变化约 **3.3 秒**后从悬浮窗隐藏；再次切到视频应用不会重新显示早已过期的句子。新的字幕会重新出现。
- 不引入 ML Kit、DeepSeek、云识别、翻译、记录文本到磁盘或更多权限。

## 真机验收（小米 13）
1. **不要卸载 R3.1**。直接升级 0.3.2 APK，保持已导入的离线英文模型。
2. 启动 SYSTEM 音频、开启跨应用显示，切回此前可以录到声音的英文视频。
3. 连续听 3–5 分钟：新的话应更新/替换上一个字幕片段，而不是累积几屏转录；文本最多 2 行，不能盖住过多画面。
4. 连续说话没有停顿也应按长度截成可读小片段；长句的 ASR 原文不能出现 240 字符截断或假性 final。
5. 暂停 5 秒：悬浮层自动隐藏；继续说话要重新出现。回应用再回视频，不能让过期句子重新悬浮。
6. 确认视频操作触摸、通知栏停止、投屏授权、悬浮窗权限撤销仍正常。
7. 观察是否存在迟迟不切句/过早切句/重复词。这次是**基于时间和长度的展示分段**，不是语义标点恢复，模型有背景音乐时不会承诺准确判断每一个自然句子。

**阶段结论需以 Actions 和真机为准。**
